## 1. Navigation & Auth

### Stack
- **LoginScreen** / **SignupScreen** — email + password auth via Supabase
- **OnboardingScreen** — first-run setup (interests + visitor type)
- **Main** — 5-tab bottom navigator

### Bottom Tabs
| Tab | Screen | Icon |
|-----|--------|------|
| Map | MapScreen | Map |
| Quests | QuestsScreen | Target |
| Route | RouteBuilderScreen | Route |
| Collection | CollectionScreen | Briefcase |
| Profile | ProfileScreen | User |

### Auth behaviour
- Supabase session restored on app launch via `supabase.auth.getSession()`
- `onAuthStateChange` keeps store in sync; calls `syncFromSupabase()` on sign-in
- `initialRoute` resolves to `Login → Onboarding → Main` based on auth + onboarding state
- Loading spinner shown while Zustand store hydrates from AsyncStorage

## 2. Onboarding

Two-step wizard on first launch.

**Step 1 — Interests**
- 6 category tiles: Architecture, Food, Nature, History, Art, Nightlife
- Multi-select; at least one required to proceed
- Selected tiles get a coloured border

**Step 2 — Visitor type**
- Two cards: *Visitor* (tourist) / *Local*
- Changes recommendation logic and daily challenge targets throughout the app

On completion: interests + visitor type + username saved locally (AsyncStorage) and synced to Supabase user profile.

## 3. Map Screen

### Map
- Interactive **TomTom WebView** map centred on user location
- Fallback to Dublin city centre coords when location unavailable
- Landmark pins rendered as tappable markers with category colour coding
- Active expedition member dots shown as animated pulsing pins

### HUD & Overlays
- **TopHUD** — persistent status strip
- **Battery warning banner** — shows when battery is low/critical; communicates route cap
- **Animated quest progress strip** — displays active quest name, progress bar, and "n of m landmarks" below the map

### Floating Actions
- **Radar FAB** — opens Nearby sheet (landmarks within selected radius)
- **Plus FAB** — opens share menu with three options:
  - Continue an existing expedition
  - Start a new expedition
  - Share a discovered spot

### Contextual Greeting
Generated by `getContextualGreeting()` — adapts to time of day, weather, and visitor type (e.g. *"Rainy day, Niraj — Best indoor spots, picked for you"*).

## 4. Quests Screen

Purple header band containing the active quest; white scroll area below.

### Active Quest Card (header)
- Category badge (emoji + label)
- Quest title
- Animated progress bar (Animated.timing, 900ms)
- `n of m landmarks found` label
- Thumbnail row — circular slots, filled slots show ✓, empty show ?
- XP pill + estimated time pill

### Quest Complete State
When `progress >= target`, the card switches to:
- CheckCircle2 icon
- "Quest Complete!" heading
- "Claim {xp} XP →" button — calls `completeQuest()` which banks XP and clears the active quest

### Daily Challenge Card
- Day-seeded category (deterministic — same for all users with the same interests on the same day)
- Target: 1 check-in (tourist) or 2 check-ins every other day (local)
- Progress bar + `progress/target · +{xpBonus} XP bonus` label
- **Claim** button appears when achieved; turns into a green ✓ badge after claimed

### Suggested Quests (horizontal scroll)
- 3 cards, excluding active and completed quests
- Sorted by stated interests (tourist) or least-explored category (local — novelty-first)
- Each card shows gradient top panel, title, difficulty dots (1–3), XP, and **Start** button

### Explorer Type Card
- Derives type from most-visited category in collection
- Falls back to onboarding interest if collection is empty
- Types: Heritage Seeker, Culinary Explorer, Wilderness Scout, Gallery Wanderer, Time Traveller, Night Owl

## 5. Route Builder Screen

Personalised walking route generator — the 5th tab.

### Time Budget
- Preset chips (horizontal scroll): **30 min · 1 hr · 1.5 hr · 2 hr · 3 hr**
- **Custom chip** — shows clock icon; when tapped reveals inline picker:
  - Hours column (0–12) with +/− buttons
  - Minutes column (0–55, snaps to 5 min) with +/− buttons
  - Live label updates on the chip (e.g. `2h 30m`)
  - "Includes spots further afield" note appears when total > 90 min
- Battery cap: chips are individually disabled only if *that duration* would be reduced by battery (< 20% → 60 min cap; < 10% → 30 min cap)

### Context Banners
- **Weather banner** — adapts copy and colour: rainy (blue, indoor spots prioritised), clear (amber, great day), windy (grey, sheltered spots)
- **Battery banner** — shown only when battery cap reduces the selected budget

### Category Filter
- 6 chips with category colour and lucide icon
- Pre-selected from user's onboarding interests
- At least one must remain selected

### Route Building
1. On-demand location permission request — calls `getCurrentLocation()` directly; alert only shown if permission permanently denied
2. Battery cap applied via `getAdjustedBudget(timeBudget)`
3. `fetchAllLandmarks()` + `fetchUserDwellTimes()` fetched in parallel (no radius cap — all landmarks eligible)
4. Pool filtered to selected categories
5. Full recommendation engine scores pool (7 signals — see §11)
6. Personalised dwell times overlaid per category from user history
7. **Nearest-neighbor** algorithm builds route within time budget; handles `lat`/`lon` fields from Supabase
8. Per-waypoint walk time computed from Haversine distance at 4.5 km/h

### Route Output
- Stats bar: **stops · total min · total XP**
- Waypoint cards: numbered step bubble, category gradient strip, lucide icon, landmark name, category, walk time, visit time, XP
- **Open in Maps** button — deep-links to Apple Maps with saddr + daddr waypoints

## 6. Collection Screen

Gallery of all landmarks the user has checked into.

### Pin Grid
- 3-column grid, each pin `(screenWidth − 56) / 3` px wide
- **3D circular gradient pins** — `expo-linear-gradient` per category colour
- **Lucide vector icon** centred on each pin (no emoji)
- **Metallic tier ring**: silver (public), gold (discovered), purple/hidden (hidden)
- Shadow wrapper + `overflow:hidden` inner layer pattern (prevents shadow clipping)
- Landmark name + XP label beneath each pin

### Category Filter Bar
- Horizontal scroll: All, Architecture, Food, Nature, History, Art
- Filters the grid in real time

### Placeholder Pins
- Three shimmer animated pins labelled "?" shown in a "Still out there" row below the grid
- Encourages continued exploration

### Pin Detail Modal
- Full-screen overlay; tap backdrop to close
- **3D rotatable pin** — PanResponder with capture-phase handlers drives `rotateX`/`rotateY` via `Animated.Value`; spring-back on release
- Transform: `[{ perspective: 900 }, { rotateX }, { rotateY }]` (useNativeDriver: false — perspective requires layout driver)
- Shows: landmark name, tier pill, category pill, XP earned in gold (#FFD700), collected date

## 11. Adaptive Recommendation Engine

`mobile/src/utils/recommendations.js`

### `calculateScore(landmark, preferences, context)` — 7 signals, 0–100

| Signal | Effect |
|--------|--------|
| Interest match | +20 if landmark category is in user's stated interests |
| Visitor type — local | +15 hidden tier, +8 discovered tier |
| Visitor type — tourist | +8 public tier, up to +10 from landmark points |
| Category novelty | +12 never explored, +5 lightly explored (< 3 visits) |
| Already collected | −60 strong penalty |
| Accessibility | +5 if meets minimum accessibility level |
| Weather — rain | +18 indoor, −15 outdoor |
| Weather — clear | +6 outdoor |
| Weather — hot/windy | +8/+5 indoor |
| Time — morning | +10 Food, +8 Nature |
| Time — afternoon | +8 Architecture, +8 History, +6 Art |
| Time — evening | +18 Nightlife, +10 Art, +8 Food |
| Time — night | +14 Nightlife |
| Battery low/critical | +12 short visits (≤ 20 min), +8 close landmarks (< 300 m), −8 long visits (> 45 min) |

### `buildContext({ weather, batteryTier })`
Derives `timeOfDay` (morning / afternoon / evening / night) from current hour.

### `getContextualGreeting(userName, context, visitorType)`
Returns greeting + subtitle line adapting to rain, cold, clear mornings, evening, and visitor type.

### `buildPreferences({ interests, visitorType, collection })`
Convenience builder from Zustand store state → `preferred_categories`, `visitor_type`, `category_counts`, `collected_ids`, `accessibility_min`.

## 12. XP & Progression System

### XP per check-in (by tier)
| Tier | XP |
|------|----|
| Public | 150 |
| Discovered | 320 |
| Hidden | 600 |

### Level
`level = floor(totalXP / 500) + 1`

`totalXP = sum(collection xpEarned) + questBonusXP`

### Streak
Counts consecutive days (back from today) with at least one check-in.

## 13. Quest System

6 quests, each with a category, emoji, base XP, and difficulty (1–3):

| ID | Title | Category | Base XP | Difficulty |
|----|-------|----------|---------|------------|
| q_arch | Heritage Trail | Architecture | 600 | 3 |
| q_food | Street Food Safari | Food | 400 | 1 |
| q_history | Through the Ages | History | 550 | 2 |
| q_art | Art Discovery | Art | 500 | 2 |
| q_nature | Into the Wild | Nature | 450 | 2 |
| q_night | After Dark | Nightlife | 700 | 3 |

### Adaptive target
`target = min(3 + floor(level / 3), 8)`

Starts at 3 check-ins, grows by 1 every 3 levels, caps at 8.

### Adaptive XP
`xp = round(baseXp × target / 3)`

XP scales proportionally with target so higher-level players earn more.

### Progress
`progress = collection.filter(c => c.category === quest.category).length` (capped at target)

### Completion flow
1. `isComplete` when `progress >= target` — quest card switches to "Quest Complete!" state
2. User taps "Claim {xp} XP →"
3. `completeQuest(id)` — adds scaled XP to `questBonusXP`, adds id to `completedQuests`, clears `activeQuestId`
4. Completed quests are excluded from active selection and suggested list

## 14. Daily Challenge

A fresh challenge every day, deterministically seeded by date and interests.

- **Category**: `cats[floor(Date.now() / 86400000) % cats.length]` — same category for all users with same interests on the same day
- **Target**: 1 check-in (tourist) or 2 check-ins every other day (local)
- **XP bonus**: `target × 75`
- **Progress**: check-ins matching the category made since midnight today
- **Claim**: `claimDailyChallenge()` — adds xpBonus to questBonusXP, records `dailyClaimed[today]`
- Resets automatically at midnight (new `toDateString()` key)

## 15. State Management

`mobile/src/store/useStore.js` — Zustand + AsyncStorage

### Persisted state
`hasOnboarded`, `userName`, `interests`, `visitorType`, `collection`, `activeQuestId`, `completedQuests`, `questBonusXP`, `dailyClaimed`

### Auth state (not persisted — Supabase handles session)
`authUser { id, email, name }`, `isAuthenticated`

### Key actions
| Action | Description |
|--------|-------------|
| `checkIn(landmark)` | Adds to collection, awards tier XP, syncs to Supabase |
| `setActiveQuest(id)` | Sets active quest |
| `completeQuest(id)` | Claims quest XP, marks completed |
| `claimDailyChallenge()` | Claims daily XP bonus |
| `completeOnboarding(interests, name, type)` | Saves profile locally + Supabase |
| `syncFromSupabase()` | Merges server collection + profile on login |
| `hydrate()` | Restores persisted state from AsyncStorage on app start |

### Computed getters
`getTotalXP()`, `getLevel()`, `getCurrentXP()`, `getStreak()`, `getActiveQuest()`, `getSuggestedQuests()`, `getDailyChallenge()`, `getExplorerType()`, `getDNAStats()`, `getStats()`

## 16. Services & Hooks

### `services/supabase.js`
| Function | Description |
|----------|-------------|
| `fetchAllLandmarks(lat, lon)` | Fetches all landmarks, annotates with distance from user |
| `fetchNearbyLandmarks(lat, lon, radius)` | Filters to radius (metres), sorted by distance |
| `saveCheckIn(userId, landmark, xp)` | Upserts collection row |
| `fetchCollections(userId)` | Returns user's collected landmarks |
| `saveUserProfile / fetchUserProfile` | Profile CRUD |
| `fetchUserDwellTimes(userId)` | Avg visit duration per category from collection history |
| `fetchCategoryCounts(userId)` | Visit count per category |
| `createExpedition / joinExpedition / leaveExpedition` | Expedition lifecycle |
| `fetchActiveExpeditions(lat, lon)` | Nearby active expeditions |
| `fetchMessages / sendMessage` | Expedition group chat |
| `subscribeToMessages / subscribeToDMs` | Supabase Realtime subscriptions |

### `services/location.js`
- `getCurrentLocation()` — requests permission on-demand, returns `{ latitude, longitude }`

### `services/tomtom.js`
- `haversineDistance(lat1, lon1, lat2, lon2)` — returns distance in **metres** (R = 6,371,000)
- Lat/lon → screen pixel projection for WebView map rendering

### `hooks/useLocation`
- Continuous location tracking hook; used by Map and RouteBuilder screens

### `hooks/useWeather`
- Fetches weather from OpenWeather for given coordinates
- Returns `{ isRaining, isCold, isHot, isWindy, isClear, temp, description }`

### `hooks/useBattery`
- `expo-battery` — live battery level + charging state
- Tiers: `ok` (≥ 50% or charging), `medium` (20–50%), `low` (10–20%), `critical` (< 10%)
- `getAdjustedBudget(minutes)` — caps at 60 min (low) or 30 min (critical)
- `reduceGPS` flag — reduces location poll frequency when battery < 20%

### `utils/routing.js`
- `buildRoute(start, landmarks, timeBudgetMin)` — nearest-neighbor greedy algorithm
- Handles `lat`/`lon` Supabase fields with `lat ?? latitude` fallback
- Skips landmarks with no valid coordinates
- Walk speed: 4.5 km/h

### `utils/distance.js`
- `calculateDistance(lat1, lon1, lat2, lon2)` — Haversine, returns **km**
- `estimateWalkingTime(distanceKm, pace)` — slow 3 km/h / moderate 4.5 / fast 6

## 17. Theme System

`mobile/src/context/ThemeContext.js`

- `useTheme()` hook provides `theme` object and `setMode(mode)` action
- **Exploration mode** (default): warm cream background `#FFFDF8`; primary `#F5A623` (amber)
- **Quest mode**: purple `#7C3AED` header; called by QuestsScreen on mount, restored on unmount
- `TopHUD` component renders consistently across screens using theme values
- `CATEGORY_COLORS` map drives pin gradients, waypoint strips, and category chips throughout the app
